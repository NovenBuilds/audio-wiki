## 一、实施目标与范围

第一版交付单用户、自托管的网页程序，将使用者自备的人格技能、书籍知识和真人克隆音色组合成可持续听讲、提问并续播的课程。

以已确认的完整管线为依据，按以下顺序推进：

**实施计划 → 功能清单 → 架构设计 → 开发任务拆分 → 纵向闭环 → 首版完善 → 实际验收。**

本计划确定实施顺序、阶段产物和完成条件；具体页面交互、接口字段、数据库结构及技术框架在后续功能清单和架构设计阶段确定，本轮不提前生成这些文档。

### 首版交付范围

- 人格技能、书籍知识技能、声音档案独立管理、版本化保存并组合使用。
- 初期支持导入现成人格与书籍技能包，保留后续集成提炼流程的边界。
- 支持书籍章节与原文依据管理，按需取用原文。
- 支持音频文件直接导入、视频文件提取音轨，以及试听和选择参考片段。
- 支持真实声音克隆、音色试听与朗读预设。
- 将内容生成与朗读节奏编排分开，按模型实际能力处理语速、停顿和表达要求。
- 支持课程目录、讲稿审阅、分段合成、连续播放与进度恢复。
- 支持文字提问、同一目标音色回答和返回原位置续播。
- 提供资料库、人格与声音、课程工作台、播放与提问、服务设置五类页面。
- 凭据由后端环境提供；长任务、音频缓存及播放位置持久保存。

首版不以六款模型全部接入为发布条件。内置完整人格／书籍提炼、语音提问、流式首播、移动端后台播放、多用户服务和原生客户端进入后续迭代。

## 二、实施阶段与交付条件

| 阶段 | 实施工作 | 交付物 | 完成条件 |
|---|---|---|---|
| 0．整理规划基线 | 归档完整管线、记录已确认范围和最新实验状态 | 本计划、归档后的完整管线、有效入口链接 | 文档职责清楚，引用有效，没有覆盖其他实验记录 |
| 1．规划功能清单 | 围绕五类页面整理操作流程、功能优先级、输入输出、异常反馈和验收场景 | 首版功能清单 | 每项首版功能有明确完成标准；后续功能单独列出 |
| 2．完成架构设计 | 确定前后端、后台任务、存储、模型适配、播放状态和部署方案 | 架构设计及关键决策记录 | 技术栈、模块边界、核心数据对象和接口契约确定，可直接拆分开发 |
| 3．建立开发基础 | 建立独立实施仓库，配置开发环境、基础页面、配置加载与持久化任务 | 可启动的应用骨架 | 浏览器能访问；后端能读取凭据引用；任务与状态在重启后保留 |
| 4．交付纵向闭环 | 用一份人格技能、一个书籍章节及知识技能、一个真实克隆音色完成讲授与问答 | 可实际使用的闭环版本 | 生成讲稿、播放、文字提问、同音色回答和续播全部跑通 |
| 5．完善首版能力 | 补齐音视频入口、资产复用、朗读控制、缓存、任务恢复、长章节与五类页面 | 首版候选版本 | 首版功能清单逐项完成，关键异常场景可恢复 |
| 6．实际验收与交付 | 使用真实材料完整试用，修复阻断问题，整理部署与恢复说明 | 首版程序、验收记录、使用说明 | 用户接受内容与声音体验，连续讲授及提问续播可靠 |

各阶段以完成条件判断进度，不因文档、页面或代码数量增加而视为完成。未确定投入工时前，不编造日历排期。

### 阶段 0：规划资料归档

退出规划模式后执行：

- 新建 `plan/`，保存本计划。
- 将完整管线文档从 `research/` 移入 `plan/`，保留原文件名。
- 修正移动文档中的研究资料相对链接，并更新项目入口对它的引用。
- 实验记录和资产清单继续保留在原位置；不将研究证据混入计划目录。
- 检查文档链接、变更范围和工作区状态，不提交或推送。

### 阶段 1—2：功能与架构规划

功能清单按“必须交付、后续增强”分类，覆盖正常操作、失败反馈与恢复操作。

架构设计必须确定以下事项，完成后再进入开发：

- 浏览器、应用后端、后台工作进程及本地推理服务的职责。
- 书籍、技能包、参考素材、声音档案、课程、讲稿、音频片段、任务与播放位置之间的关系。
- 素材导入、课程生成、合成任务、任务状态、提问与续播所需接口。
- 模型能力声明方式：声音准备、语速、停顿、表达指令、流式输出和取消能力。
- 文件保存、元数据持久化、缓存失效、任务恢复与凭据访问方式。
- 首个接入模型、部署方式、开发环境及后续本地模型连接方式。
- 首版支持的文档及媒体格式，并为不支持的格式设计明确反馈。

这些决定形成可追溯的设计记录，不能留给开发时临时猜测。

### 阶段 3—4：先跑通完整使用路径

先复用已有云端实验程序中的有效接入逻辑，检查后迁入产品代码；不直接将实验脚本当作稳定产品接口。

纵向闭环按顺序完成：

1. 导入并审阅人格技能、书籍知识技能和一个章节原文。
2. 选择已有克隆音色或准备新音色，完成短稿试听。
3. 创建课程，生成有出处的讲稿，允许修改后再合成。
4. 生成独立朗读计划，分段合成并连续播放。
5. 点击提问时保存真实播放位置，生成并朗读回答。
6. 回答结束后恢复课程，支持从当前句重听。
7. 刷新网页及重启后恢复课程、任务和已保存进度。

先证明整条链路可用，再扩展输入格式、模型数量和性能优化。

### 阶段 5：补齐可靠性与首版体验

- **素材入口**：音频直接接入；视频检测并提取音轨，多音轨可选择，无音轨或损坏时明确报错。原件、提取音轨和处理版分别保留。
- **参考处理**：支持选择时间片段、导入外部处理版及可选人声分离；不把自动去净背景音乐作为首版承诺。
- **朗读控制**：按模型能力映射语速和停顿；不支持原生控制时明确标示后处理方式。
- **资源复用**：修改讲稿只重做受影响片段；更换声音复用书籍解析和知识技能。
- **任务恢复**：接收失败优先恢复已有结果；请求结果不明时保留待核对状态，避免自动重复合成或重复创建音色。
- **播放调度**：首节优先，有限预生成；提问回答优先于后续课程合成，迟到的旧回答不得进入当前播放。
- **运行记录**：保存任务耗时、实际返回用量与失败原因；费用估算和实际账单分开记录。

## 三、测试与验收计划

| 验收方向 | 必测场景 | 通过标准 |
|---|---|---|
| 内容与人格 | 同一章节使用指定人格和知识技能生成讲解、回答细节问题 | 体现已选思维与表达特点，事实可追溯；依据不足时不编造 |
| 素材入口 | 音频、单／多音轨视频、无音轨及损坏文件 | 正确导入或明确报错，原件不覆盖，参考片段可追溯 |
| 声音体验 | 短稿及完整章节试听 | 用户分别接受音色、节奏、背景与完整性 |
| 连续播放 | 多片段组成完整章节 | 顺序正确，无丢段、重复或异常衔接 |
| 提问续播 | 段中提问、连续追问、中断回答 | 回答与课程分离，原进度不丢失，旧回答不误播 |
| 状态恢复 | 刷新、关闭网页、后端重启 | 已完成产物可复用，保存进度可恢复，不重复创建已完成任务 |
| 异常与缓存 | 超时、下载失败、修改讲稿、更换音色 | 状态明确，仅重做必要产物，不因重试机制隐性重复计费 |
| 部署与隐私 | 全新环境启动、资料访问、配置与日志检查 | 可依说明运行，服务密钥不进入浏览器、仓库或日志 |

自动测试覆盖状态转换、参数适配、缓存与异常恢复；真实服务验证覆盖最终音频和完整交互。离线检查通过、音频可解码均不能替代用户试听与端到端验收。

首版交付同时记录真实首播等待、连续播放表现、提问耗时及使用成本，用于后续性能目标制定，不预填未经验证的指标。

## 四、实施约束与默认原则

- 当前已有六款模型反馈；2026-11-05 新增七份调速／降噪样本尚待用户试听，不将其预先认定为改善成功。
- 首个模型是工程接入选择，不代表最终效果排名；复用现有成果优先于重新实验。
- 人格与声音可以分别选择；更换任一项不应要求重建全部资产。
- 原文依据按章节与段落保存；原文检索按需要启用，不强制引入向量数据库。
- 自动提炼后续仍采用类女娲和 book-to-skill 方法，不能退化为简单语气模板或章节摘要。
- 应用实施进入独立仓库；苗圃保留项目卡、规划与来源链接。仓库建立及持续执行事实满足条件后，再更新生命周期状态。
- 实际音视频、权重、缓存和真实凭据不进入苗圃 Git 仓库。
- 本计划之后依次规划功能清单与架构设计；本轮不开发程序、不新跑模型、不创建远端资源。
